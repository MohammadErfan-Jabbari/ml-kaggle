  Here are categorically different paradigms we haven't tried:              
                                                                            
  ---                                                                       
  Genuinely Different Approaches                                            
                                                                            
  1. Density Ratio Reweighting (KLIEP/uLSIF)                                
                                                                            
  Instead of hand-tuned species weights (0.05x, 3.0x...), we learn the      
  optimal importance weights by estimating p_test(x) / p_train(x). This is  
  the principled solution for covariate shift.                              
                                                                            
  2. Domain Adversarial Neural Networks (DANN)                              
                                                                            
  Train a feature extractor that explicitly cannot distinguish train from   
  test. Forces domain-invariant representations. Well-studied, often        
  works.                                                                    
                                                                            
  3. Transductive Label Propagation                                         
                                                                            
  Build a similarity graph over train+test. Propagate labels through the    
  graph. Uses test structure directly - not just pseudo-labels from a       
  model.                                                                    
                                                                            
  4. Test-Time Training (TTT)                                               
                                                                            
  Train a self-supervised auxiliary task (e.g., predict masked MALDI        
  features). At test time, adapt the model using the auxiliary loss on each 
  test sample. Model "specializes" to test distribution.                    
                                                                            
  5. Optimal Transport Domain Adaptation                                    
                                                                            
  Align train and test distributions using Wasserstein distance. Map        
  training samples to where they'd be in test space.                        
                                                                            
  ---                                                                       
  My recommendation: Start with Density Ratio Reweighting - it's the most   
  direct attack on the covariate shift problem and doesn't require neural   
  network training. If that doesn't work, move to DANN or Label             
  Propagation.

  ---
  Your Question: Should Validation Be Included in PCA Fitting?

  Short answer: YES, include validation in PCA fitting.

  Here's the reasoning:

  The Setup
  ┌────────────┬─────────────┬───────────────────────┐
  │  Dataset   │ PCA Fitting │      Label Usage      │
  ├────────────┼─────────────┼───────────────────────┤
  │ Train      │ ✅ Include  │ Yes (training)        │
  ├────────────┼─────────────┼───────────────────────┤
  │ Validation │ ✅ Include  │ Yes (evaluation only) │
  ├────────────┼─────────────┼───────────────────────┤
  │ Test       │ ✅ Include  │ No (unlabeled)        │
  └────────────┴─────────────┴───────────────────────┘
  Why Include Validation in PCA Fitting?

  1. PCA is unsupervised - no label leakage. It only learns feature correlations, not target relationships.
  2. Consistency with test - The whole point of transductive DR is that test data influences the learned subspace. If validation is excluded from PCA but test is included, your validation conditions don't match test conditions. Validation would be misleading.
  3. Better principal components - More data = more stable covariance estimation = better PCA.
  4. The "leak" is harmless - The only information that flows from validation to the model is "here are some feature vectors that exist" - not their labels.

  What You Keep Separate

  - Labels: Only train labels are used for classifier training
  - Validation evaluation: Done on held-out validation set as usual
  - The validation split itself: Same672samples, same test-like distribution

  The Flow

  1. Load all data: train (3360) + test (1000) = 4360 samples
  2. Fit PCA on ALL4360 samples (unsupervised)
  3. Transform everything: X_all_reduced
  4. Split back: X_train_reduced (2688), X_val_reduced (672), X_test_reduced (1000)
  5. Train classifier on X_train_reduced with y_train
  6. Evaluate on X_val_reduced with y_val
  7. Predict on X_test_reduced

  └────────────────┴───────────┴───────────────┴──────────────────────────────┘

  3. Excluding validation would make val conditions DIFFERENT from test conditions
  4. More data = more stable principal components

❯ can we use PLS LGB wit hthe self supervised? or it doens't help? 

● Great question! Yes, we can combine PLS with self-training, but it works differently:

  PLS is supervised - it needs labels to fit. So we can't do "transductive PLS" on unlabeled test data directly.

  But here's the clever twist: In self-training, as we add pseudo-labels to test samples, we can re-fit PLS including those pseudo-labeled samples. This makes PLS "adaptive" to the test distribution.

  The Approach: Iterative PLS + Self-Training

  Iteration 1:- Fit PLS on labeled train data only
    - Transform train + test
    - Train LGB, predict on test
    - Pseudo-label confident test samples

  Iteration 2:
    - Fit PLS on (labeled train + pseudo-labeled test)  ← PLS now sees test patterns!
    - Transform everything
    - Train LGB, predict
    - Add more pseudo-labels

  Iteration N:
    - PLS has learned from many pseudo-labeled test samples
    - Representation is adapted to test distribution

  This is essentially what made the mega-blend work (PLS-LGB got 0.83862), but with self-training on top.

  Want me to implement this? It's a quick modification to add PLS inside the self-training loop instead of PCA.
